Was sind KI-Agenten oder Agentic AI?

  • Baha Erdoğan
  • KI

Vom Antworten zum Handeln

Bittest du einen Chatbot, einen Besprechungsraum zu buchen, erklärt er dir, wie man einen Besprechungsraum bucht. Bittest du einen Agenten darum, schaut er in den Kalender, findet einen freien Termin, bucht den Raum und verschickt die Einladung. Genau dieser Unterschied zwischen einem Text über eine Aufgabe und der tatsächlich erledigten Aufgabe ist gemeint, wenn von Agentic AI die Rede ist.

Das Sprachmodell dahinter kann in beiden Fällen dasselbe sein. Was sich ändert, ist die Software drumherum: eine Schleife, in der das Modell einen Schritt wählt, ihn ausführt, sich das Ergebnis ansieht und neu entscheidet.

Was ein KI-Agent eigentlich ist

Ein KI-Agent ist ein Programm, das statt einer einzelnen Frage ein Ziel bekommt. Um es zu erreichen, zerlegt er die Arbeit in Schritte, ruft die Werkzeuge auf, die ihm zur Verfügung stehen (eine Such-API, eine Datenbank, einen Code-Interpreter, ein E-Mail-Programm), und macht weiter, bis das Ziel erreicht ist oder ihm die Möglichkeiten ausgehen.

Drei Dinge unterscheiden ihn von einem gewöhnlichen Aufruf eines Sprachmodells:

  • Er plant. Aus einer Bitte wie „Fasse die Support-Tickets des letzten Quartals zusammen und markiere alles Dringende“ werden mehrere kleinere Aufgaben: Tickets abrufen, gruppieren, die dringenden lesen, die Zusammenfassung schreiben.
  • Er handelt. Das Modell kann Werkzeuge aufrufen, und deren Ergebnisse bestimmen, was es als Nächstes tut.
  • Er korrigiert sich selbst. Schlägt eine Abfrage fehl oder liefert sie nichts Brauchbares, probiert der Agent einen anderen Weg, statt dir einfach die Fehlermeldung zurückzugeben.

Wie das im Inneren funktioniert

Egal mit welchem Framework sie gebaut sind: Die meisten Agenten folgen heute demselben Grundzyklus.

  1. Planen. Das Modell liest das Ziel und entscheidet, was zuerst zu tun ist. Manche Systeme schreiben vorab einen vollständigen Plan, andere entscheiden Schritt für Schritt.
  2. Handeln. Das Modell wählt ein Werkzeug und füllt dessen Parameter aus. Ausgeführt wird der Aufruf vom umgebenden Code, nicht vom Modell selbst. Für die Sicherheit ist dieses Detail entscheidend.
  3. Beobachten. Die Ausgabe des Werkzeugs landet wieder im Kontext des Modells. Ist das Ergebnis wie erwartet? Ist die Aufgabe erledigt?
  4. Erinnern. Bei längeren Aufgaben führt der Agent Notizen: was er versucht hat, was funktioniert hat, was der Nutzer bevorzugt. Dieses Gedächtnis kann ein einfaches Protokoll sein oder eine Vektordatenbank.

Die Schleife läuft, bis das Modell entscheidet, dass es fertig ist. Weil jeder Schritt vom vorherigen abhängt, steht das Verhalten eines Agenten erst zur Laufzeit fest. Man kann den Code nicht lesen und genau wissen, was er tun wird. Ein Großteil der Ingenieursarbeit besteht darin, mit dieser Tatsache umzugehen.

Wo Agenten heute schon nützlich sind

Die bisher besten Einsatzgebiete haben eines gemeinsam: Die Aufgabe besteht aus vielen kleinen Schritten, und jeder davon lässt sich leicht überprüfen.

  • Softwareentwicklung. Coding-Agenten lesen ein Repository, nehmen eine Änderung vor, lassen die Tests laufen und reparieren, was dabei kaputtgeht. Die Testsuite liefert ihnen ein klares Erfolgssignal.
  • Betrieb. Ein Agent kann Metriken überwachen, eine Auffälligkeit bemerken, die passenden Logs einsammeln und für die Rufbereitschaft eine erste Diagnose entwerfen.
  • Recherche und Analyse. Ein Data Warehouse abfragen, Zahlen vergleichen und aufschreiben, was sich verändert hat: Für Menschen ist das mühsam, für einen Agenten passt es gut, solange jemand die Schlussfolgerungen prüft.

Autonomie braucht Grenzen

Ein Agent, der E-Mails verschicken kann, kann auch die falsche E-Mail verschicken. Sobald ein Modell handeln darf, ist ein Fehler keine schlechte Antwort mehr, sondern etwas, das bereits passiert ist. Gut gebaute Agentensysteme haben deshalb ein paar Gewohnheiten gemeinsam:

  • Enge Berechtigungen. Der Agent bekommt nur die Werkzeuge, die er wirklich braucht, wo immer möglich nur mit Lesezugriff. Riskanter Code läuft in einer Sandbox.
  • Ein Protokoll jedes Schritts. Jeder Werkzeugaufruf wird samt Parametern geloggt, damit später nachvollziehbar ist, warum der Agent so gehandelt hat.
  • Eine menschliche Freigabe. Daten löschen, Geld ausgeben oder Kunden anschreiben wartet auf die Zustimmung eines Menschen.

Wie es weitergeht

Für viele Agentenaufgaben sind die Modelle schon gut genug. Schwierig ist inzwischen die Technik drumherum: lange Aufgaben auf Kurs halten, Systeme testen, die sich bei jedem Durchlauf anders verhalten, und entscheiden, wie viel Freiheit man ihnen lässt. Teams, die einen Agenten als verteiltes System mit einer unzuverlässigen Komponente behandeln statt als schlauen Assistenten, bauen am Ende meist Systeme, denen sie vertrauen können.
